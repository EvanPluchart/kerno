Kerno 2026.11.2 turns the AI assistant into a conversation beside your work, shows foreign keys in every
grid with one gesture to follow them, compares the rows of two tables, backs up a database on several
connections at once, and learns of a new version without being restarted.

If you run an earlier version, Kerno offers this update by itself: a dialog at launch, the proposal in the
status bar, or "Check for updates" in the About window.

## Install

| System | File |
|---|---|
| macOS, Apple Silicon | `Kerno-2026.11.2-macos-arm64.dmg` |
| Debian, Ubuntu (x86_64 / arm64) | `kerno_2026.11.2_amd64.deb` / `kerno_2026.11.2_arm64.deb` |
| Any Linux with glibc 2.31 or newer | `kerno-2026.11.2-linux-x86_64.tar.gz` / `kerno-2026.11.2-linux-aarch64.tar.gz` |
| AppImage | `Kerno-2026.11.2-x86_64.AppImage` / `Kerno-2026.11.2-aarch64.AppImage` |

`SHA256SUMS` lists the checksum of each file. The steps for each system are in the
[README](https://github.com/EvanPluchart/kerno#install). There is no Windows build.

On macOS the app is not notarized by Apple: the first time, open System Settings ▸ Privacy & Security and
click **Open Anyway**, or run `xattr -dr com.apple.quarantine /Applications/Kerno.app`.

## New

- **Foreign keys seen and followed.** A foreign-key column carries a small link mark in its header, with
  where it leads in its tooltip. On the cell under the pointer or the selected one, an arrow opens the
  referenced table filtered on that value: click it, ⌘-click the value, or press ⌘↓. In the record view
  too, and in every query result whose columns come from a table: a join, a few columns, an alias, a
  read-only connection, a SQLite file. A column that is in two foreign keys offers both tables.
- **Data compare.** "Compare data with…" on a table (the tree, a data tab's menu, Server ▸ Tools, the
  palette): pick the other table, on the same connection or another of the same engine family; Kerno reads
  both in key order and shows what only one side has and what differs, one row per key, with filters and
  both sides' values. A million rows against a million takes a few seconds and little memory. "Open
  script" writes the INSERT, UPDATE and, when you tick it, DELETE statements that make the target like the
  source into a query tab on the target: nothing runs until you run it, and the target's read-only and
  production rules apply then.
- **A faster backup.** "Faster: back up on 8 connections at once" in the simple backup view of a PostgreSQL
  database: pg_dump writes a folder, one file per table, which Kerno restores like any backup. About three
  times faster when the data is spread over several tables; a single very large table gains little.
- **The AI assistant is a conversation.** A panel at the side of the window (⇧⌘J), one conversation per query
  tab: follow-ups refine the answer, which arrives as it is written. Each SQL block has Insert, Replace and
  Copy. Still off until you turn it on in Settings ▸ AI, only the endpoint you set, and nothing an answer
  says runs by itself.
- **Ask in the editor.** "AI: Ask Here…" (⌘⇧H) opens a field under the statement at the cursor; the proposal
  is shown as a diff, removed and added lines marked, with Accept (one undo step) and Reject. A further
  sentence refines it in place.
- **Fix an error in one click.** "Fix with AI" under a failed statement's error and beside its mark: the fix
  comes back as the same diff, and is never run.
- **Ask from a right-click.** On a table: ask about it, explain it, write a query on it, generate test data
  (opened in a new tab, never run). On columns: explain them. On a result: explain it, or ask about the
  selection. Each opens the panel with its subject ready, and sends only when you press Enter.
- **A richer context for the assistant.** With the names it already had: each column's type and whether it
  can be NULL, the primary key, the foreign keys and the indexes of the tables a request is about.

## Better

- **An update found without restarting.** A Kerno left open checks again when six hours of real time have
  passed, the Mac asleep or not, and when it wakes or its window comes back to the front. The update dialog
  shows once per version, so a second release in the same day is offered too.
- **The DBeaver import takes SSH jump servers.** A tunnel's jump servers come with it, a chain of several
  included, through the system's OpenSSH; under each connection the preview says what was left out and what
  to check. A tunnel on port 2222 is no longer imported on 22 (DBeaver writes such numbers as `2222.0`).
- **The filter under a query's result proposes its columns**, as a table's WHERE field does, and
  Ctrl+Space opens the list in both.
- **The command palette finds words in any order**: "sql new" finds New SQL Editor. One Escape closes it.
- **The Edit menu has Undo, Redo, Cut, Copy, Paste and Select All** (macOS), for the editor, the fields and
  the grids.
- **Tabs and bars that hold still.** The tab strip no longer starts in the middle of a tab; nothing in a
  query tab's bar moves when a run starts or ends (Cancel has its own place, left of History); the mark of
  the statement being run is seen to breathe.
- **Dialogs.** The connection dialog keeps its buttons in view in a short window; a restore takes the path
  typed in its File field without Enter and says "No such file" in words; "Test connection" says where the
  password really came from; the toolbar's New SQL editor opens on the connection selected in the tree.
- **A table tab whose connection was closed** keeps its rows readable and greys what needs the server, with
  Connect to bring it back.
- A foreign key's arrow no longer stays on a row the pointer left.
- What the assistant is sent holds names, types and keys only: an index on an expression goes as
  `(expression)`, a table tab's statement goes with a `?` in place of each value of its filter, and rows go
  only when you tick them, with their count said.

The full list, with the tests behind each item, is in
[docs/FEATURES.md](https://github.com/EvanPluchart/kerno/blob/main/docs/FEATURES.md).

## Known limits

- The macOS build is signed ad hoc, not notarized.
- Foreign keys: no mark on a column a query computes (an expression) nor on a view's column on PostgreSQL,
  MySQL and MariaDB; a key of several columns is followed only when the result holds them all; in a
  self-join a key's columns are taken from the first of the two.
- A faster backup is PostgreSQL's: mysqldump has no usable parallel mode. A faster compression (zstd) is not
  offered, since not every pg_dump is built with it.
- Data compare: the same engine family on both sides (PostgreSQL with PostgreSQL, MySQL with MariaDB), not
  SQLite; a key the target holds unique is needed; at most 10,000 differences are kept and written to the
  script (the counts go on); each side is read as it is at that moment, not both at one instant; the script
  has no BEGIN and COMMIT of its own (use manual commit to try it); JSON whose keys are in another order
  counts as different on PostgreSQL `json` and MariaDB.
- The Edit menu's new entries are in the macOS menu bar; Kerno has no menu bar on Linux.
- The assistant: a conversation lasts for the run and is not stored; an answer's text cannot be selected with
  the mouse (Copy is there); in the editor only a fenced SQL block is offered to accept, and the proposal's
  card covers the lines under its statement.
- The limits of the earlier releases that this one does not change are in their notes:
  [2026.11.1](https://github.com/EvanPluchart/kerno/releases/tag/v2026.11.1),
  [0.3.1](https://github.com/EvanPluchart/kerno/releases/tag/v0.3.1),
  [0.3.0](https://github.com/EvanPluchart/kerno/releases/tag/v0.3.0).
