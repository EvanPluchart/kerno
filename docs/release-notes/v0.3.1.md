Kerno 0.3.1 answers the first reports of people replacing DBeaver by Kerno: a restore that stopped on a
missing role, a table's rows that now load as you scroll, a script whose progress you see in the editor, and
each connection's SQL scripts in its menu.

If you run 0.2.0 or 0.3.0, Kerno offers this update by itself: a dialog at launch, or the proposal in the
status bar.

## Install

| System | File |
|---|---|
| macOS, Apple Silicon | `Kerno-0.3.1-macos-arm64.dmg` |
| Debian, Ubuntu (x86_64 / arm64) | `kerno_0.3.1_amd64.deb` / `kerno_0.3.1_arm64.deb` |
| Any Linux with glibc 2.31 or newer | `kerno-0.3.1-linux-x86_64.tar.gz` / `kerno-0.3.1-linux-aarch64.tar.gz` |
| AppImage | `Kerno-0.3.1-x86_64.AppImage` / `Kerno-0.3.1-aarch64.AppImage` |

`SHA256SUMS` lists the checksum of each file. The steps for each system are in the
[README](https://github.com/EvanPluchart/kerno#install). There is no Windows build.

On macOS the app is not notarized by Apple: the first time, open System Settings ▸ Privacy & Security and
click **Open Anyway**, or run `xattr -dr com.apple.quarantine /Applications/Kerno.app`.

Coming from 0.2.0 on macOS: the first time you open each saved connection, macOS asks one last time for the
keychain, as the [0.3.0 notes](https://github.com/EvanPluchart/kerno/releases/tag/v0.3.0) explain. From 0.3.0
nothing is asked.

## New

- **A restore that names a missing role says so, and runs again without it.** A production backup restored
  into a local PostgreSQL used to stop at `ALTER … OWNER TO …` with pg_restore's raw output. Kerno now says
  first which role the backup names and that this server has none, then offers "Restore without owners and
  privileges…" (`--no-owner --no-privileges`), shown and confirmed like any restore. The simple restore view
  has the same choice as a checkbox, "Leave out the backup's owners and privileges". It reads the SQL the tool
  printed, so it works whatever language pg_restore speaks.
- **A table's rows load as you scroll.** No more pages to turn: reaching the last rows of a table reads the
  next ones and adds them under those already there, as a query result does. The selection, the place in the
  grid and the pending edits stay. The footer says "Rows 1–3,000 of 12,345" and holds "Fetch size: 1,000":
  click it to change how many rows one load reads, for this tab. "Fetch more" (Ctrl+Alt+N) and "Fetch all"
  (Ctrl++) work in a table as in a result.
- **See where a running script stands.** While statements run, the margin left of the line numbers marks
  each one the run has reached: running, done, failed, cancelled, or refused on a read-only connection. The
  status bar says "running statement 3 of 12 · 4.20 s". The marks stay after the run, until the next one or
  the first edit, so a failure shows where the script stopped.
- **A connection's SQL scripts in its menu.** Right-click a connection ▸ "SQL scripts": its saved queries by
  folder, then the `.sql` files last opened or saved on it. A click opens the script on that connection,
  connecting first when needed, and goes to its tab when it is already open. "SQL Scripts of Selected
  Connection…" in the command palette lists them all.

## Better

- The `url` crate is updated to 2.5.9 for the advisory RUSTSEC-2026-0592 (a crash on a crafted `blob:` URL),
  published after 0.3.0.

The full list, with the tests behind each item, is in
[docs/FEATURES.md](https://github.com/EvanPluchart/kerno/blob/main/docs/FEATURES.md).

## Known limits

- The macOS build is signed ad hoc, not notarized.
- Restore: a plain SQL file run by `psql` has its owners in its own text, so there is no "without owners"
  for it; Kerno says what to do instead. Nothing was added for a MySQL or MariaDB `DEFINER` that names a
  missing user.
- Table data: the fetch size chosen in the footer lasts for the tab; Settings ▸ Grid stays the default. A
  table without a key and a view are read again from their first row at each load, so that no row is repeated
  or skipped: far down a very large one, each load takes longer. Rows inserted or deleted by someone else
  between two loads can shift what the next load brings; Refresh reads them again.
- The marks of a running script do not scroll the editor to the statement that runs, and have no tooltip:
  the status bar says in words what they show.
- A connection's menu lists its ten last saved queries and ten last files ("All scripts…" for the rest), and
  leaves out the saved queries usable with any connection ("Saved queries…" reaches them).
- The limits of 0.3.0 that this release does not change (SQLite, schema compare, the PDF, the connection
  dialog in a short window, the toolbar's "New SQL editor") are in the
  [0.3.0 notes](https://github.com/EvanPluchart/kerno/releases/tag/v0.3.0).
