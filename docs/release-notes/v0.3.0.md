Kerno 0.3.0 adds SQLite, a compare of two schemas, the export of a schema as a document (PDF, HTML, Markdown,
DBML, SQL, Mermaid), an extensions manager for PostgreSQL and a simpler backup view, and on macOS it stops
asking for your keychain password.

If you run 0.2.0, Kerno offers this update by itself: a dialog at launch, or the proposal in the status bar.

## Install

| System | File |
|---|---|
| macOS, Apple Silicon | `Kerno-0.3.0-macos-arm64.dmg` |
| Debian, Ubuntu (x86_64 / arm64) | `kerno_0.3.0_amd64.deb` / `kerno_0.3.0_arm64.deb` |
| Any Linux with glibc 2.31 or newer | `kerno-0.3.0-linux-x86_64.tar.gz` / `kerno-0.3.0-linux-aarch64.tar.gz` |
| AppImage | `Kerno-0.3.0-x86_64.AppImage` / `Kerno-0.3.0-aarch64.AppImage` |

`SHA256SUMS` lists the checksum of each file. The steps for each system are in the
[README](https://github.com/EvanPluchart/kerno#install). There is no Windows build.

On macOS the app is not notarized by Apple: the first time, open System Settings ▸ Privacy & Security and
click **Open Anyway**, or run `xattr -dr com.apple.quarantine /Applications/Kerno.app`.

## After updating on macOS: one last question from the keychain

Until now your saved passwords were in the macOS Keychain, and because Kerno is not signed by Apple, macOS
asked for your login password again after every update. From 0.3.0, saved passwords are kept in Kerno's own
encrypted file (Settings ▸ Passwords), so this stops.

The first time you open each saved connection after this update, macOS asks one last time: Kerno reads that
password from the keychain and moves it to its file. Allow it, or refuse and type the database password
instead. After that the keychain is not read again for that connection, and a new connection never touches it.

What this protects: the file is encrypted and readable by your account only, so a copy of it, a file search
or another user of the Mac sees nothing. A program running under your account could read it, as with
DBeaver's saved passwords or `~/.pgpass`. If you prefer the keychain, choose it in Settings ▸ Passwords. On
Linux nothing changes: the Secret Service stays the default.

## New

- **SQLite.** Open a database file: browse its tables, views, indexes and triggers, run queries, edit rows,
  create and alter tables with what SQLite allows said in plain words, export and import.
- **Schema compare.** "Compare with…" on a schema or a database: pick the other side, on the same connection
  or another one of the same engine family. Kerno lists what differs (tables, columns, indexes, keys,
  constraints, views, routines, types, triggers) and opens the script that brings the target to the source.
  Nothing runs by itself.
- **Export a schema as a document.** "Export schema…" on a schema, a database, a table or the ER diagram:
  everything, or the tables and views you tick. PDF and HTML in three styles (Kerno light, Kerno dark,
  plain), with the diagram, a page per table, real text you can search, and bookmarks in the PDF; Markdown as
  a data dictionary; DBML; SQL in an order that runs; Mermaid. Structure only: no row is read, and no host,
  user or file path is written.
- **Extensions manager for PostgreSQL.** One view per database: what is installed and what the server offers,
  with install, update and drop behind their SQL and a confirmation. The tree lists the installed ones.
- **Backup and restore in one simple view.** The file, the format and Start; the full wizard is one click
  away as "Advanced settings".
- **A dialog when a new version is out,** once per run, with Update, Later and Skip this version.

## Better

- Settings has a list of sections on the side, rows grouped in panels and option cards with drawn previews.
- The window opens again where it was and as large as it was, on the same display.
- A selected row, cell or entry is seen at a glance in both themes.
- Notifications no longer cover the toolbars.
- "New SQL editor" on a connection that is not open connects first.
- Replacing a file chosen in the macOS save panel asks once, not twice.

The full list, with the tests behind each item, is in
[docs/FEATURES.md](https://github.com/EvanPluchart/kerno/blob/main/docs/FEATURES.md).

## Known limits

- The macOS build is signed ad hoc, not notarized.
- SQLite: no backup or restore, no administration tab, no copy of tables to or from it, no attached
  databases, no `kerno file.db` on the command line; a change that SQLite can only do by rebuilding the table
  is refused with the reason; results of a free query cannot be edited (a table's own data can).
- Schema compare: the same engine family on both sides (PostgreSQL with PostgreSQL, MySQL with MariaDB), not
  SQLite. Indexes, keys and constraints that only the target has are dropped by the script; tables, columns
  and other objects wait for "Also drop what only the target has". On PostgreSQL the order of columns is not
  compared and a new enum label is not written as `ALTER TYPE … ADD VALUE`.
- The PDF draws a character that Inter and JetBrains Mono lack (Chinese, Arabic, emoji) as an empty box; the
  text still copies. The diagram is fitted to one page.
- Kerno's password file was not run on Linux before this release, where the default stays the Secret
  Service.
- In a window less than about 750 px high, the result of "Test connection" pushes the connection dialog's
  buttons below the window: make the window taller.
- The toolbar's "New SQL editor" opens on the connection of the active tab, not on a connection only selected
  in the tree: use "New SQL editor" in that connection's own menu.
- Memory at rest is about 152 MB with one connection and one query tab.
