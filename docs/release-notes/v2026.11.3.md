Kerno 2026.11.3 lets a PostgreSQL connection choose which databases it shows, says before any click which
databases your account may not open, and comes for Windows for the first time, as a preview.

If you run an earlier version on macOS or Linux, Kerno offers this update by itself: a dialog at launch, the
proposal in the status bar, or "Check for updates" in the About window.

## Install

| System | File |
|---|---|
| macOS, Apple Silicon | `Kerno-2026.11.3-macos-arm64.dmg` |
| Debian, Ubuntu (x86_64 / arm64) | `kerno_2026.11.3_amd64.deb` / `kerno_2026.11.3_arm64.deb` |
| Any Linux with glibc 2.31 or newer | `kerno-2026.11.3-linux-x86_64.tar.gz` / `kerno-2026.11.3-linux-aarch64.tar.gz` |
| AppImage | `Kerno-2026.11.3-x86_64.AppImage` / `Kerno-2026.11.3-aarch64.AppImage` |
| Windows, x86_64 (preview) | `kerno-2026.11.3-windows-x86_64.zip` |

`SHA256SUMS` lists the checksum of each file. The steps for each system are in the
[README](https://github.com/EvanPluchart/kerno#install).

On macOS the app is not notarized by Apple: the first time, open System Settings ▸ Privacy & Security and
click **Open Anyway**, or run `xattr -dr com.apple.quarantine /Applications/Kerno.app`.

On Windows, unpack the zip and run `kerno.exe`: there is nothing else to install. Windows may warn about an
unknown publisher: the executable is not signed.

## New

- **Choose the databases a PostgreSQL connection shows.** "Databases shown" on the Database line of the
  connection dialog: All, Those this account can open, or Only the default database. The tree and the
  database pickers follow as soon as the connection is saved, without a reconnect; a line under the databases
  says how many are hidden, and a click on it opens the setting. A connection imported from DBeaver shows what
  DBeaver showed.
- **A database your account may not open says so before any click.** It is dimmed in the tree, and opening it
  shows "This account may not connect here." at once, without a connection attempt and without the red error
  cut by the row. Its menu keeps only what still works there.
- **Windows, a preview.** One zip with `kerno.exe`, its icon and everything it needs inside. The app starts and
  draws its window; nobody has used it on Windows yet, so take it as a first look (its limits are below).

## Better

- **A global backup names what it leaves out.** The databases the account may not open are listed under the
  databases and at the top of the run's log, instead of pg_dumpall stopping on the first of them; a saved task
  reads them again at each run.
- **A table backed up alone** no longer shows a command for its whole schema while the tables are still being
  listed.
- **A refused database** says "You may not connect to database “x”." first, then the server's own words.
- **Linux: Query History is Ctrl+Alt+E.** It was on Ctrl+Y, which is Redo in every text field and in the
  editor on Linux: Redo works there again. macOS keeps ⌘Y.
- **Linux: a cancelled backup** no longer leaves its incomplete file behind, and a folder picture chosen a
  moment ago is no longer removed by the clean-up of unused pictures.
- The packages are built on GitHub's runners from this release on, with the scripts that built them before;
  each Linux package is started on a machine of its own architecture before the release is made.

The full list, with the tests behind each item, is in
[docs/FEATURES.md](https://github.com/EvanPluchart/kerno/blob/main/docs/FEATURES.md).

## Known limits

- The macOS build is signed ad hoc, not notarized. The Windows executable is not signed.
- Windows is a preview: no installer; no update check (a new version is not announced there); the tunnel
  through the system's OpenSSH is not available (the built-in SSH client is); `~/.ssh`, `.pgpass` and `.my.cnf`
  are not read; the local `pg_dump`, `mysqldump` and their kin are not detected, so backup and restore are
  not expected to work; saved passwords and Kerno's files rely on the access rights of your Windows profile
  folder.
- "Databases shown" is PostgreSQL's: MySQL and MariaDB already list only what the account may see. It has no
  name patterns of its own: the tree's Filter ▸ hides databases by name.
- A database refused by the server's own rules (`pg_hba.conf`) and not by a missing CONNECT privilege is not
  known in advance: it is not dimmed, and its error speaks of the login.
- The limits of the earlier releases that this one does not change are in their notes:
