Kerno 2026.11.1 makes a restore from another server go through at the first try, and faster, imports your
connections from DBeaver, and adds what the first people replacing DBeaver asked for in a day of use.

This is the release after 0.3.1: Kerno's versions are now the year, the month and the number of the release
in that month. If you run 0.2.0, 0.3.0 or 0.3.1, Kerno offers this update by itself: a dialog at launch, the
proposal in the status bar, or "Check for updates" in the About window.

## Install

| System | File |
|---|---|
| macOS, Apple Silicon | `Kerno-2026.11.1-macos-arm64.dmg` |
| Debian, Ubuntu (x86_64 / arm64) | `kerno_2026.11.1_amd64.deb` / `kerno_2026.11.1_arm64.deb` |
| Any Linux with glibc 2.31 or newer | `kerno-2026.11.1-linux-x86_64.tar.gz` / `kerno-2026.11.1-linux-aarch64.tar.gz` |
| AppImage | `Kerno-2026.11.1-x86_64.AppImage` / `Kerno-2026.11.1-aarch64.AppImage` |

`SHA256SUMS` lists the checksum of each file. The steps for each system are in the
[README](https://github.com/EvanPluchart/kerno#install). There is no Windows build.

On macOS the app is not notarized by Apple: the first time, open System Settings ▸ Privacy & Security and
click **Open Anyway**, or run `xattr -dr com.apple.quarantine /Applications/Kerno.app`.

## New

- **A restore says before it runs what the server lacks.** For a PostgreSQL archive, Kerno reads the
  backup's list and asks the server: an extension the server does not have (such as `pgaudit` on a laptop) and
  owner roles it does not have are said in plain words before Start, with the boxes to leave them out already
  ticked. One run instead of one failure per missing thing.
- **A faster restore.** "Faster: restore on 8 connections at once" in the simple restore view, for custom and
  directory archives: a large production backup went from 450 s to 219 s. It is not all or nothing: a
  statement that fails is skipped and the rest is restored, and Kerno now says so ("went to the end past 1
  error it ignored", with the statement) instead of "failed".
- **Import from DBeaver.** "Import from DBeaver…" takes a project export (`.dbp`) or a `data-sources.json`:
  folders, PostgreSQL, MySQL, MariaDB and SQLite connections with their SSH and SSL settings, their
  environment (shown and changeable in the preview; DBeaver's own connection types can become environments),
  and the project's scripts as saved queries of their connection. Saved passwords on request, straight into
  Kerno's password store.
- **A connection's environment in the sidebar.** A connection that is not local shows its environment as a
  small tag (Staging, Production, yours) before you connect to it.
- **The WHERE field proposes the table's columns.** Type in a table's WHERE field: its columns, then the
  words of a condition; Tab or Enter accepts.
- **Recently used commands.** The command palette (⌘K) opens on the five commands you ran last: ⌘K then
  Enter repeats the last one.
- **⌘← closes the whole tree.** With the focus in the sidebar's tree: objects, connections and folders. In a
  text field ⌘← still goes to the start of the line.
- **Check for updates from the About window,** and "Check for Updates…" in the Kerno menu. From the next
  release on, the update dialog also says briefly what the new version brings.

## Better

- **A sort keeps your place across the columns.** So do a filter, a refresh and an Apply on a wide table.
- The order of the columns of a table, their widths, the hidden and pinned ones and the sort are kept after
  closing the tab and after a restart (proved by a test; it was already so).
- The hover of a tab's close cross is a small centred square.

The full list, with the tests behind each item, is in
[docs/FEATURES.md](https://github.com/EvanPluchart/kerno/blob/main/docs/FEATURES.md).

## Known limits

- The macOS build is signed ad hoc, not notarized.
- When a newer version is found, Kerno now also reads that release's notes from GitHub to show them (nothing
  about you is sent; nothing is asked when update checks are off).
- Restore: leaving an extension out can make what depends on it fail in turn; that failure is said the same
  way. A plain SQL file has no "leave out" and no parallel restore. A missing role whose name holds a space
  is shown by its last word.
- Import from DBeaver was written from DBeaver's source and tried on one real export: jump servers, pasted
  certificates and network profiles are reported, not imported; exports older than DBeaver 6.1.3 are refused;
  a project protected by a master password comes without its user names and passwords.
- The field that filters a query's result on the server has no proposals yet; Ctrl+Space does not open the
  list in a WHERE field (typing does).
- The limits of 0.3.0 and 0.3.1 that this release does not change are in their notes:
  [0.3.1](https://github.com/EvanPluchart/kerno/releases/tag/v0.3.1),
  [0.3.0](https://github.com/EvanPluchart/kerno/releases/tag/v0.3.0).
