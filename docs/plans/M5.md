## Part 1 — Catalog for completion (drivers) — `opus`

Goal: one cheap call that returns everything completion needs, instead of one `table_structure` per table.

Files: `crates/kerno-core/src/driver.rs`, `crates/kerno-postgres/src/introspect.rs` (+ `session.rs` to
forward), `crates/kerno-mysql/src/introspect.rs` (+ `session.rs`), tests in
`crates/kerno-postgres/tests/introspect.rs` and `crates/kerno-mysql/tests/introspect.rs`.

1. Add to the `Session` trait: `async fn completion_catalog(&self) -> Result<kerno_core::sql::Catalog>;`
   (doc comment: every non-system schema with its relations, their columns and foreign keys, the routine
   names, and the search path).
2. PostgreSQL, three statements run with the session's own query helper (look at how `objects` and
   `table_structure` run and decode their queries, and reuse that):
   - Relations and columns:
     ```sql
     SELECT n.nspname, c.relname, c.relkind::text, a.attname, format_type(a.atttypid, a.atttypmod)
     FROM pg_catalog.pg_class c
     JOIN pg_catalog.pg_namespace n ON n.oid = c.relnamespace
     LEFT JOIN pg_catalog.pg_attribute a ON a.attrelid = c.oid AND a.attnum > 0 AND NOT a.attisdropped
     WHERE c.relkind IN ('r', 'p', 'f', 'v', 'm')
       AND n.nspname NOT IN ('pg_catalog', 'information_schema')
       AND n.nspname NOT LIKE 'pg\_toast%' AND n.nspname NOT LIKE 'pg\_temp%'
     ORDER BY n.nspname, c.relname, a.attnum
     ```
     `relkind` to `RelationKind`: `r` Table, `p` PartitionedTable, `f` ForeignTable, `v` View,
     `m` MaterializedView.
   - Foreign keys (one row per key, columns as arrays in key order):
     ```sql
     SELECT n.nspname, c.relname, fn.nspname, fc.relname,
            ARRAY(SELECT a.attname FROM unnest(k.conkey) WITH ORDINALITY AS u(attnum, ord)
                  JOIN pg_catalog.pg_attribute a ON a.attrelid = k.conrelid AND a.attnum = u.attnum
                  ORDER BY u.ord)::text[],
            ARRAY(SELECT a.attname FROM unnest(k.confkey) WITH ORDINALITY AS u(attnum, ord)
                  JOIN pg_catalog.pg_attribute a ON a.attrelid = k.confrelid AND a.attnum = u.attnum
                  ORDER BY u.ord)::text[]
     FROM pg_catalog.pg_constraint k
     JOIN pg_catalog.pg_class c ON c.oid = k.conrelid
     JOIN pg_catalog.pg_namespace n ON n.oid = c.relnamespace
     JOIN pg_catalog.pg_class fc ON fc.oid = k.confrelid
     JOIN pg_catalog.pg_namespace fn ON fn.oid = fc.relnamespace
     WHERE k.contype = 'f'
     ```
     If decoding `text[]` is awkward with the existing helper, use `array_to_string(…, chr(31))` and split.
   - Routines: `SELECT DISTINCT n.nspname, p.proname FROM pg_catalog.pg_proc p JOIN pg_catalog.pg_namespace n
     ON n.oid = p.pronamespace WHERE n.nspname NOT IN ('pg_catalog', 'information_schema')`.
   - Search path: `SELECT unnest(current_schemas(false))` (in order).
3. MySQL / MariaDB (a "schema" is a database; system ones are `information_schema`, `mysql`,
   `performance_schema`, `sys`):
   - `SELECT c.table_schema, c.table_name, t.table_type, c.column_name, c.column_type
     FROM information_schema.columns c JOIN information_schema.tables t
     ON t.table_schema = c.table_schema AND t.table_name = c.table_name
     WHERE c.table_schema NOT IN (…system…) ORDER BY c.table_schema, c.table_name, c.ordinal_position`
     (`table_type` `VIEW` is a View, anything else a Table).
   - `SELECT table_schema, table_name, constraint_name, column_name, referenced_table_schema,
     referenced_table_name, referenced_column_name FROM information_schema.key_column_usage
     WHERE referenced_table_name IS NOT NULL AND table_schema NOT IN (…) ORDER BY table_schema, table_name,
     constraint_name, ordinal_position` (group rows by constraint).
   - `SELECT routine_schema, routine_name FROM information_schema.routines WHERE routine_schema NOT IN (…)`.
   - Search path: `[DATABASE()]` when the session has a database, else empty.
   - MySQL 8 returns `information_schema` column names in upper case: read columns by position.
4. Tests (integration, both drivers, MySQL and MariaDB): the catalog contains the fixture tables with their
   columns in order (`shop.orders`: `id, customer_id, status, …` on PostgreSQL; the `kerno` database on
   MySQL: check the fixture `tests/fixtures/mysql/01_schema.sql` for names), one known foreign key
   (`orders.customer_id` → `customers.id`), a view with kind `View`, a routine name, and the search path.
   No system schema is listed.

Acceptance: `cargo test -p kerno-postgres --test introspect`, `-p kerno-mysql --test introspect` green with
`KERNO_REQUIRE_CONTAINERS=1`; clippy clean for the workspace (the trait gained a method: every implementor
compiles, including test doubles if any — `grep -rn "impl Session for"`).

## Part 2 — Completion and Format SQL in the editor (app) — `opus`, after Part 1

Files: `crates/kerno/src/query/tab.rs`, new `crates/kerno/src/query/completion.rs`,
`crates/kerno/src/query/mod.rs`, `crates/kerno/src/actions.rs`, `crates/kerno/src/workspace.rs`,
`crates/kerno/src/main.rs` (Edit menu), `crates/kerno/src/ui_tests.rs`.

1. **Catalog per tab.** `QueryTab` gains `catalog: Rc<RefCell<Arc<Catalog>>>` (empty by default). Load it
   with `session.completion_catalog()` through `bridge::spawn`:
   - in `follow_connection` when the connection is connected, using `connections.meta_session(id)` when the
     tab's database is the connection's own, otherwise the tab's own session (`self.session(cx)`);
   - again after a run in which a statement of kind DDL finished (`classify(...).kind`: look at
     `StatementKind` in `kerno-core/src/sql/classify.rs` for the DDL kinds);
   - reset to empty in `set_target`. Guard results with `self.generation` like the other loads.
   - `search_path`: when the tab has a schema (`target.schema`), put it first.
2. **Provider.** The kit's editor asks a completion provider: read the trait in the pinned sources
   (`grep -rn "completion_provider" ~/.cargo/registry/src/*/gpui-base-0.9.1/src/input/`; it is set through
   `editor_state.lsp_mut().completion_provider = Some(Rc::new(…))`). Implement it in `query/completion.rs`
   as `SqlCompletion { catalog: Rc<RefCell<Arc<Catalog>>>, rules: LexRules, quote: … }`:
   - on a request at a cursor offset, call `kerno_core::sql::complete(text, offset, &catalog, rules, &quote)`
     on the text of the **statement at the cursor only** (use `split_statements` + `statement_at`, then shift
     the offsets), and map `Completion { replace, items }` to the kit's completion items (label, inserted
     text, replaced range, detail, a kind icon if the kit has one);
   - `rules` and `quote` come from the session's dialect (`dialect.lex_rules()`, `dialect.quote_ident`).
     They change with the tab's target: rebuild the provider in `set_target` / `follow_connection`.
   - the popup opens while typing a word and after `.`; it must not accept an item on space (check the
     kit's trigger options).
   - The provider must be cheap: it runs on the UI thread on every keystroke (measured at 0.05–0.15 ms in
     release for 2,000 tables; keep it that way: no catalog clone per call, borrow the `Arc`).
3. **Format SQL.** Action `FormatSql` in `actions.rs` (`command!("format_sql", "Format SQL", "Editor",
   ["secondary-shift-i"], ["beautify", "pretty", "indent"], FormatSql)`), handler in `workspace.rs` calling
   `QueryTab::format(window, cx)`: format the selection when there is one, else the whole text, with
   `format_sql(text, rules)`; replace through `editor.replace_all(...)` (one undo step, as `toggle_comment`
   does) and keep the cursor at the start of what was formatted. Text already formatted is left untouched
   (no undo step). Add "Format SQL" to the Edit menu in `main.rs`.
4. Tests in `ui_tests.rs` (PostgreSQL; MySQL for quoting):
   - `completion_proposes_tables_columns_and_joins`: connected tab, wait for the catalog (add a test
     accessor `catalog_ready()`), ask the provider directly for `select * from shop.ord|` → contains
     `orders`; `select o.| from shop.orders o` → its columns; `from shop.orders o join |` → first item is the
     join on the foreign key; on MySQL a table named with a reserved word is inserted quoted with backticks
     (create it in a `Scratch`).
   - `typing_in_the_editor_opens_completion_and_enter_accepts_it`: type `select * from shop.cust`, the popup
     shows `customers` (find how the kit exposes the open menu to tests; if it cannot be observed, assert
     through the editor state), accept, the text is `select * from shop.customers`.
   - `the_catalog_follows_ddl`: run `create table kerno_ui_c.t (…)` in the tab, then completion proposes it.
   - `format_sql_rewrites_the_selection_or_everything_as_one_undo_step`.
5. Capture (main session): `m5-completion-light.png` (popup open on a join), `m5-format-light.png`.

## Part 3 — `split_statements` is quadratic (core) — `opus` or `sonnet`

File: `crates/kerno-core/src/sql/split.rs` only. For every delimiter found, the function scans all tokens
again (`tokens.iter().filter(...)`), so a script of N statements costs N × tokens. Rewrite the scan as one
pass over the tokens (keep the behaviour: all existing tests in the file and in `classify.rs`, `params.rs`,
`complete.rs`, `format.rs` stay green, including the MySQL `DELIMITER` cases). Add a test that splits
20,000 statements (`"select 1;\n"` repeated) and asserts it takes under 200 ms in a debug build (measure
with `Instant`; the old code takes seconds) and a note in the function doc. Remove the `ponytail:` note about
this in `complete.rs` if it no longer applies.

Also reported in the lexer (`lex.rs`), to fix in the same part if small, else to list in the report:
`1.5e-3` lexes as three tokens; `U&'…'` lexes as Word, Punct, String. If fixed, the formatter's special
cases for them can go; run the formatter corpus tests.

## Part 4 — Close a tab that holds something (app) — `opus`, small

Files: `crates/kerno/src/workspace.rs`, `crates/kerno/src/query/tab.rs`, `crates/kerno/src/data/tab.rs`,
`ui_tests.rs`. Closing a tab (Cmd+W, the tab's ×) asks first when it would lose something:

- a query tab whose session has `tx_state() != Idle` (an open transaction would be rolled back): alert
  dialog "Close and roll back?" with Roll back and close / Cancel;
- a data tab with pending changes (`pending_count > 0`): "Discard N pending changes?";
- a file-backed query tab with unsaved text: "Close without saving?" (text of unnamed tabs is restored at
  the next start only while the tab is open, so closing them needs no question).

Use `window.open_alert_dialog` (see the delete-connection confirmation in `sidebar.rs` /
`connections` for the pattern; button ids `ok` / `cancel`). Tests: one per case, asserting that Cancel keeps
the tab and its state, and that confirming closes it (and, for the transaction, that the server no longer
sees the uncommitted row).
