## Part 1 — Editing comfort (app) — `opus`

Files: `crates/kerno/src/query/grid.rs`, `crates/kerno/src/data/tab.rs`, `ui_tests.rs`.

1. **Enum and boolean cells.** A cell of an enum column (`ColumnInfo::enum_values` not empty) or a boolean
   column is edited through a dropdown of its values (plus NULL when the column is nullable) instead of
   free text. `Grid::page` receives `writable: Vec<bool>` today; replace it by a small per-column struct
   (`writable`, `choices: Vec<String>`, `nullable`). Keep free text for everything else.
2. **A cell being typed in shows its type's alignment**: right-align the editor of numeric columns.
3. **Binary cells**: still not typed in; the value viewer opens (already the case). No change.
4. **Paste**: with a cell selected and text in the clipboard, Cmd+V sets the cell (one pending edit); with
   a TSV block, it fills the rectangle starting at the selected cell, stopping at the last row and column
   (cells that take no value are skipped). Handled in `DataTab`'s key handler next to Cmd+C.
5. **Delete / Backspace** on a selection without an open editor sets the selected cells to NULL when
   nullable (same code path as "Set NULL").
6. **Revert cell**: row menu entry "Revert row" exists; add Cmd+Z in the grid (no editor open) to drop the
   most recent pending change. Keep it simple: `Pending` gains an undo stack of the previous state (clone of
   the three collections; pages are at most a few thousand rows).

MySQL `ENUM`), `pasting_fills_cells_from_the_clipboard`, `delete_sets_null_and_undo_takes_changes_back`;
unit tests for the undo in `kerno-core/src/pending.rs`.

## Part 2 — Counting large tables without stalling (core + app) — `opus`, small

Today the total is `SELECT count(*)` after each page; on a very large table it holds the session for
seconds and the next page waits for it. Change: before counting an **unfiltered** table, read the planner's
estimate; when the estimate is above 1,000,000 rows, show "about 12,345,678 rows" and a "Count exactly"
button in the footer instead of counting; filtered pages and smaller tables count as now.

- `Dialect::estimated_rows_sql(&self, table: &TableRef) -> String`: PostgreSQL `SELECT reltuples::bigint FROM
  pg_catalog.pg_class c JOIN pg_catalog.pg_namespace n ON n.oid = c.relnamespace WHERE n.nspname = '…' AND
  c.relname = '…'` (−1 means never analysed: count exactly); MySQL / MariaDB `SELECT table_rows FROM
  information_schema.tables WHERE table_schema = '…' AND table_name = '…'`. Strings through
  `quote_string`.
- `DataTab`: `total: Option<Total>` with `Total::Exact(u64) | Total::About(u64)`; "Next" is enabled while
  the page is full when the total is not exact.
- Test: on `analytics.big_table` (1,000,000 rows, PostgreSQL) and its MySQL counterpart the footer is
  either exact or "about …" with the button, and "Count exactly" gives `1,000,000`. Lower the threshold in
  the test through a `#[cfg(test)]` setter rather than creating a larger table.
