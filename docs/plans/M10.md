## Part 1 — `cargo deny` with no ignored advisory — `opus`

`deny.toml` ignores RUSTSEC-2023-0071 (timing side channel in `rsa`, pulled by `russh`'s `rsa` feature:
`Cargo.toml` pins `russh = { version = "0.65", default-features = false, features = ["ring", "rsa",
"flate2"] }`). GOAL criterion 1 forbids the ignore. In this order:

1. Check crates.io for a `russh` release that depends on a fixed `rsa` (≥ 0.10.0 final, or 0.9 patched):
   `cargo search russh`, read its `Cargo.toml` on docs.rs / the repository. If one exists, upgrade, fix the
   API changes in `crates/kerno-core/src/ssh.rs`, remove the ignore.
2. Otherwise drop the `rsa` feature: RSA **key files** can then no longer sign; RSA keys held by the SSH
   agent still work (the agent signs), and Ed25519 / ECDSA key files work. Detect an RSA key file when the
   tunnel is configured or opened and return a clear error ("RSA key files are not supported in this build:
   load the key in your SSH agent, or use an Ed25519 key"), shown in the connection dialog's test result.
   Check that the SSH test container (`tests/fixtures/ssh`, `crates/kerno-core/tests/ssh.rs`) still covers
   password, Ed25519 key with passphrase, and agent; replace an RSA-key test by the new error's test.
3. Remove the ignore from `deny.toml`; `cargo deny check` clean (advisories, licences, bans, sources).
   Update DECISIONS D-013 and the README's "Known limits" if RSA key files are refused.

## Part 2 — Secrets never reach the disk or the log (test) — `opus`, small

GOAL criterion 3. New UI test `no_secret_is_written_to_the_data_directory_or_the_log`: with a data
directory in a tempdir and file logging initialised to it (look at `logging.rs`; the test fixture uses
`AppPaths::under(tempdir)`), save a connection with a known, unusual password (and an SSH passphrase on a
second one), connect, run a statement, fail a connection with a wrong password, export the connections to
JSON, quit (drop the window so logs flush); then read **every file** under the data directory (SQLite
database included, as bytes), the exported JSON and the log file and assert none contains the password or
the passphrase. Same for a statement that holds a password literal (`ALTER USER … PASSWORD '…'` /
`CREATE USER … IDENTIFIED BY '…'`): the history stores it redacted (the storage layer already redacts:
find the test in `storage.rs` and extend the UI-level one). Fix whatever the test finds.

## Part 3 — Settings, keymap and keyboard coverage (app, §4.I) — `opus`

Files: `settings.rs`, a new `crates/kerno/src/settings_view.rs` (move the dialog out of `workspace.rs`),
`actions.rs`, `workspace.rs`, `theme.rs`, `query/tab.rs`, `query/grid.rs`, `ui_tests.rs`.

1. Settings view (Cmd+,) with sections: **Appearance** (system / light / dark — exists), **Fonts** (UI
   font size 12–18, editor and grid font size 11–20; the families stay the embedded Inter and JetBrains
   Mono), **Editor** (tab size 2 / 4, soft wrap, line numbers, completion on / off, font ligatures on / off
   — `>=` currently renders as a ligature; default **off** for SQL), **Grid** (page size 100–10,000, NULL
   text shown, date-time display with / without zone), **Confirmations** (confirm destructive statements —
   exists; confirm closing a tab with pending work), **Tools** (paths of `pg_dump`, `pg_restore`, `psql`,
   `mysqldump`, `mysql` from milestone 8), and a link "Open keymap file" (creates it with a commented
   example when absent, then reveals it). Each setting applies at once and is stored (`Settings::save`);
   `Settings` stays `serde(default)` so old stores load.
2. Keymap: `actions::bind_keys(path, cx)` reads the override file; make sure every command of
   `actions::COMMANDS` can be rebound or unbound, that a bad file reports its problems in a notification at
   start (not a crash), and document the format in the README. Test exists for overrides: extend for unbind.
3. Keyboard coverage: every action reachable from the palette (walk §4 A–I and add missing commands:
   connect / disconnect the selected connection, edit / duplicate / delete connection, refresh navigator,
   focus navigator filter, focus editor, focus results, next / previous result tab, toggle messages, fetch
   more / all, copy as each format, open value viewer, commit, rollback, toggle commit mode, export,
   import, backup, administration, open structure / data of the table under the cursor…). Defaults from
   CLAUDE.md §3: Cmd+Enter, Cmd+Shift+Enter, Cmd+., Cmd+T, Cmd+W, Cmd+S, **Cmd+P quick open table**, Cmd+K.
4. **Quick open (Cmd+P)**: a palette-like dialog listing the relations of the active connection (from the
   completion catalog of milestone 5; fuzzy match on `schema.table`), Enter opens the data tab,
   Cmd+Enter (or a second action) the structure tab. Test on PostgreSQL and MySQL.
5. Native menu bar on macOS: every command also sits in a menu (File, Edit, View, Query, Data, Server,
   Window, Help) with its shortcut shown (`main.rs`).

## Part 4 — UX / UI pass on every screen — main session with the `ui-ux-improver` and `ai-anti-slop`
skills for the review; fixes delegated to `opus` in bounded lists

For each screen: run the release app (light and dark), capture, look, list what is wrong, fix, capture
again. Screens: empty window (no connection), connections list and groups, new-connection dialog (engine
picker, SSL, SSH sections, test result states), password / trust prompts, navigator (loading, empty schema,
error, filter with no match), query tab (empty editor, running, results, multiple results, messages,
error with position, cancelled), EXPLAIN plan, parameter prompt, history and saved queries, value viewer,
data tab (loading, empty table, filter error, pending edits, read-only banner, review dialog), structure
tab and table editor, export / import / backup dialogs (each step, error states), admin tab, command
palette, quick open, settings, confirmations (plain, destructive, production).

Backlog already known (fix all):

- New-connection dialog: a test result stays on screen after the form changes (clear it on any change);
  "connection refused" should say what to check (host, port, server running, firewall, tunnel);
  the SSH fingerprint is not in the monospace font.
- Rename dialog: the current name is not preselected.
- Value viewer: text cannot be selected (use a read-only editor/input).
- Results: `INSERT` copies name a placeholder table (keep, but say so in the menu item's tooltip).
- Data tab: the whole grid gets a focus ring after a dialog closes (keep keyboard focus, drop the ring on
  the container or make it subtle); status bar repeats the footer (keep the status bar, shorten the footer).
- Every empty / loading / error state says what happened and what to do next (§3); server errors show
  message, detail, hint and position.
- Contrast: text at least WCAG AA in both themes (check muted text on tinted rows, the pending-change
  colours, the status bar warning). Write a unit test over the theme tokens computing contrast ratios for
  the text / surface pairs used (`theme.rs`).
- Motion under 150 ms and never blocking input; tabular figures in the grid (font feature `tnum`); engine
  logos at clear space, never recoloured beyond the vendor's rule (see DECISIONS D-019).
- Tab bar: many tabs overflow (scroll or shrink), middle-click closes, tab context menu (close others).
