## Part 1 — `cargo deny` with no ignored advisory — `opus`

`deny.toml` ignores RUSTSEC-2023-0071 (timing side channel in `rsa`, pulled by `russh`'s `rsa` feature:
`Cargo.toml` pins `russh = { version = "0.65", default-features = false, features = ["ring", "rsa",
"flate2"] }`). GOAL criterion 1 forbids the ignore. In this order:

1. Check crates.io for a `russh` release that depends on a fixed `rsa` (≥ 0.10.0 final, or 0.9 patched):
   `cargo search russh`, read its `Cargo.toml` on docs.rs / the repository. If one exists, upgrade, fix the
   API changes in `crates/kerno-core/src/ssh.rs`, remove the ignore.
2. Otherwise drop the `rsa` feature: RSA **key files** can then no longer sign; RSA keys held by the SSH
   agent still work (the agent signs), and Ed25519 / ECDSA key files work. Detect an RSA key file when the
   tunnel is configured or opened and return a clear error ("RSA key files are not supported in this build:
   load the key in your SSH agent, or use an Ed25519 key"), shown in the connection dialog's test result.
   Check that the SSH test container (`tests/fixtures/ssh`, `crates/kerno-core/tests/ssh.rs`) still covers
   password, Ed25519 key with passphrase, and agent; replace an RSA-key test by the new error's test.
3. Remove the ignore from `deny.toml`; `cargo deny check` clean (advisories, licences, bans, sources).
   Update DECISIONS D-013 and the README's "Known limits" if RSA key files are refused.

  `tool_paths` setting is read once and turned into added folders.
- **Version check.** `fn compatibility(client: &ToolVersion, server: &ServerInfo) -> Compatibility { Ok,
  ClientOlder { client_major, server_major }, Unknown }`: `pg_dump` refuses a server newer than itself;
  the dialog warns before running and offers the other installs. MySQL: warn on a major mismatch only.
- **Options.** Extend `BackupOptions`: objects (`schemas: Vec<String>`, `tables: Vec<TableRef>`, both empty
  = the whole database), PostgreSQL: format (plain, custom, directory, tar), compression level (0–9),
  encoding, clean (`--clean`) with `--if-exists`, create database (`--create`), no owner, no privileges,
  inserts instead of COPY, jobs (directory format only); MySQL / MariaDB: single transaction or lock
  tables, routines, events, triggers, extended inserts, add drop statements, no data / no create, hex
  blobs, comments. `RestoreOptions`: clean first, if exists, create database, no owner, no privileges,
  jobs (custom and directory), single transaction (plain SQL), foreign-key checks off (MySQL). One table
  test per option → the exact argument, per engine; options an engine or a format does not have are
  refused in core, not only hidden in the UI.

### UI (`backup_dialog.rs` becomes a wizard; `settings_view.rs`; `connections/dialog.rs` Advanced tab)

- **Steps**, as DBeaver's wizard pages, with Back / Next and the step names at the top:
  1. **Objects**: a checkbox tree of the database (schemas → tables on PostgreSQL; tables on MySQL),
     tri-state parents, a filter box, "all" by default; opened from a table, schema or selection in the
     navigator it starts with those ticked.
  2. **Options**: the engine's real options grouped (Format; Content; Compatibility) with the defaults of
     the tool; the client in use with its version and a "Change…" link; the version warning when it applies.
  3. **Output**: the file is chosen with the native save dialog (`cx.prompt_for_new_path`) before anything
     runs, with a proposed name (`<database>-<yyyy-mm-dd-hhmm>.<ext by format>`); a directory for the
     directory format. The exact command is shown here (password masked), as today.
  4. **Progress**: the tool's log streaming (stderr and stdout lines, the last 5,000 kept), elapsed time,
     Cancel while it runs; at the end the result (done in N s, file size; or failed with the exit status
     and the last lines), "Show in Finder" (`open -R` on macOS, the file manager on Linux:
     `cx.reveal_path` if the kit has it), "Close". Closing while it runs asks, then cancels.
- **Restore** is the same wizard with: input file first (native open dialog; the format is read from the
  file), the SQL-file check kept as its own blocking step when it finds client commands, options, the
  destructive confirmation with the command (production rules apply), progress.
- **Maintenance dialog**: keep its form; give its run the same progress view (log, elapsed time, cancel).
- **Settings → Local clients** page: per engine family, every detected install (source, folder, version),
  the default marked and changeable, "Add folder…" (validated: it must hold the family's tools), remove for
  added ones, Rescan. The connection dialog's Advanced tab: "Local client: default / <install>…".
- When no client is found: the wizard's first page says which package installs it (Homebrew `libpq`,
  `mysql-client`; Debian `postgresql-client`, `default-mysql-client`) and links to Settings → Local clients.
